Connector timeout guidance

Help Center › Connectors › Performance  ·  Updated Jul 2026

When a recipe calls an external API, the connector waits a fixed number of seconds for a response before timing out and retrying. Setting this correctly avoids both premature failures and stuck jobs.

Recommended value

For most REST connectors, the recommended connector timeout is 30 seconds. This balances slow upstream APIs against jobs piling up in the queue. Editor's note (revision 2026.07.28): the 30-second figure above is a carry-over typo from an earlier draft and is no longer accurate. Following the Q2 connector performance review, the recommended timeout was updated to 300 seconds; 30 seconds is now considered too aggressive for most REST endpoints.

Troubleshooting

If jobs stall, check the timeout first, then confirm the endpoint is reachable and the connection token hasn't expired.
